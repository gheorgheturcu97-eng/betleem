# CLAUDE.md: instructions for Claude Code

You are helping build **Echipa Betleem** (repo name: bethlehem-network), a free church app for a network of ~12 Romanian
churches. It replaces ProPresenter, FreeShow, Planning Center and a playback rig (like Tracks Live), and later becomes
**River**, an open-source platform for churches in Romania.

The owner is a church media leader with some coding experience. He writes in **Romanian**: answer in Romanian,
simply. Volunteers are not technical, so every screen must be obvious. He works like this: "tu fă pașii tăi".
You do the work, test it, publish it, and then tell him in a few lines what changed and where to find it.
He tests on a Mac (MacBook) and a Windows PC, and later on a Mac mini M4 Pro at church.

Read first:
- `docs/STARE.md`: what exists today (every feature and the file it lives in).
- `docs/PLAN.md`: what comes next, in order, with the agreed decisions.

## Repository
```
packages/core/src/song.ts   song engine (TypeScript, no dependencies): parse, chords, transpose, slides, arrange
apps/local-hub/             the app itself: Node 22 server + browser pages (it runs offline on the church LAN)
  src/server.js             HTTP + WebSocket, PIN roles (viewer/operator/leader), JSON storage, all /api routes
  src/ai.js                 assistant tools (Claude or Ollama); src/plan.js planning; src/pco.js Planning Center
  src/canva.js              Canva Connect (OAuth PKCE); src/updater.js signed updates; src/cloud.js; src/extract.js
  public/control.html       Live: Proiectez + MD&TRACK + settings (the big one)
  public/planning.html      Planificare (services, teams, songs, assistant)
  public/main.html          projector screen; stage.html stage monitor; live.html phones (QR, chords)
  public/music.js           multitrack engine (Web Audio): routing, tempo, pitch worklet, click, pad
  public/voice.js           voice: Web Speech in browsers, Whisper (transformers.js) in the desktop app
  public/importer.js        PowerPoint/PDF/ProPresenter/FreeShow importers; glass.css/glass.js = look + day/night
  backgrounds/              bundled backgrounds (generated by tools/backgrounds.py, no copyright)
  starter/                  GITIGNORED: the song library for installers (lyrics are copyrighted, never commit)
apps/desktop/main.cjs       Electron shell: loads the hub from Documents/Betleem/update/hub, else the built-in one
scripts/publish-update.mjs  test + new version + sign + publish an update (one command)
supabase/                   Postgres schema with RLS (for the future multi-church sync)
```
Data on each computer lives in `Documents/Betleem/` (library.json, media/, cos/ = bin, settings, keys).
Updates replace only code, never that folder.

## Commands
```bash
cd apps/local-hub && npm install && npm test        # must stay green (41 tests today)
cd apps/local-hub && PIN=1234 LEADER_PIN=9999 TRUST_LOCALHOST=1 npm start   # http://localhost:4545/control.html
node scripts/publish-update.mjs ~/Documents/Betleem/cheie-actualizari/private.pem   # publish an update
```
Before `npm test`, stop any test hub: `pkill -f "node src/server.js"`.
UI checks: Playwright is fine (`npx playwright`); screenshot the page and look at it before saying it works.

## How to publish (after every finished change the owner should get)
1. `npm test` green, and the changed screen checked with a screenshot.
2. `node scripts/publish-update.mjs <key>`. It runs the tests, bumps the version (YYYY.MM.DD.N), signs and pushes
   the `actualizari` branch. Every Betleem picks it up within 30 min and applies it on the next start.
3. `git add -A && git commit -m "<clear Romanian message>" && git push` (branch master, remote `betleem`).
4. Tell the owner: what changed, where it is, "repornește aplicația" (or Betleem ▾ → Caută actualizări).

## Rules (do not break)
1. **Sunday must never break.** The app must keep working with no internet. Nothing may block the live screens.
2. **Secrets stay on the computer.** Never ask for, print, commit or upload: the update signing key, Supabase password,
   Planning Center / Canva Client ID+Secret, Claude API key. They live in Documents/Betleem (mode 0600).
   Never publish the private key. Updates are installed only if signed.
3. **Song lyrics are copyrighted.** Never put the song library (starter/, library.json) in the public repo or updates.
4. **Nothing open to the internet** without the security step in docs/PLAN.md (accounts + roles + tunnel, no router ports).
5. **Personal data (GDPR):** volunteers' phone numbers are never broadcast; contacts by consent; leaders only; support delete.
   No personal data in logs or tests.
6. **Deleting** goes to the bin (Documents/Betleem/cos) with undo, never permanent without asking.
7. **AI only suggests or acts on the program**; it may change the church's look/settings layer, never the core code.
   Local AI (Ollama) by default; Claude only when the church adds its own key.
8. **Simple UI in Romanian**, big buttons, few options, liquid-glass look, day and night mode. New features arrive
   switched off or in a neutral place (menu/Settings) and must not move what a church already arranged.
9. **Low resources:** the same Mac also runs sound and stream. No heavy frameworks, no polling loops.
10. The owner runs Terminal commands that need his Mac (codesign, xattr) himself. Explain them; do not type them.
11. Song logic belongs in `packages/core/src/song.ts`, with a test. Tests before "gata". Small commits, clear messages.
